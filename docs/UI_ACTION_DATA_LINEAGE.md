# UI ACTION → DATA LINEAGE

Generated by `docs/audit/lineage_build.mjs` at commit `ec5e008` from `lineage_actions.mjs` (frontend) and `lineage_endpoints.mjs` (backend). Line numbers are resolved at build time from the source, so they match this commit. Evidence is CODE-DERIVED unless a record says LOCALLY VERIFIED or NOT VERIFIED.

Source codes: **D1** (bars-vault) · **SUPABASE** (archive_bars) · **LIVE_PROVIDER** (Yahoo 1-min, Yahoo daily, Cboe book, frankfurter.app) · **KV_SNAPSHOT** · **GITHUB_ARCHIVE** · **BROWSER_MEMORY** (page variables, localStorage) · **MIXED**.

Retention (CODE-DERIVED): D1 keeps 60 trading days (`D1_KEEP_DAYS`), Supabase 42 (`ARCHIVE_DAYS`, pruned nightly), GitHub CSVs are rebuilt from Supabase with the last 42 dates. Nothing the app reads holds data older than ~60 trading days.

## 2. "One week of 1-minute candles for AAPL" — proven path

Single-symbol week: **/bars → הורדה מרובה**, symbol AAPL, from/to = the week, **⬇ הורד** (B-10), or **הורד כל ההיסטוריה של הסימבול** (B-06, full range). Both call `GET /bars/export/:sym[?from=YYYY-MM-DD][&to=YYYY-MM-DD]` (worker.js:1957).

1. D1: `SELECT date,time,unix,OHLCV FROM bars WHERE symbol=? AND <CANON_SQL> [AND date>=?] [AND date<=?] ORDER BY date,unix`
2. Supabase, same range: `Supabase archive_bars?select=unix,o,h,l,c,v&symbol_id=eq.ID&order=unix.asc&limit=1000&offset=N[&unix=gte.from 00:00Z][&unix=lte.to 23:59:59Z] paged to 60,000 rows`
3. Merge: UNION over the WHOLE range — no date boundary split. Both stores are asked for every date. Dedup: key date:unix, FIRST WINS; D1 is taken first → D1 wins for any minute both hold.
4. Yahoo: never. GitHub: never. KV: never.
5. Failure mode: Supabase error → caught; D1 rows only, SILENTLY (no header, no note).

| DATE (example week) | SOURCE | WHY |
|---|---|---|
| any date within the last 60 trading days, AAPL tracked | D1, plus any minute only Supabase holds | union; D1 row wins when both have the minute |
| a date before AAPL was added to the tracked set (D1 never collected it; the nightly universe pass archived it) | Supabase only | D1 has no rows for that date |
| a date D1 has pruned but Supabase still holds | does not occur with the current constants (Supabase keeps 42 trading days, D1 60) | — |
| any date, symbol not tracked (universe only) | Supabase | D1 never held it |
| older than ~60 trading days | nowhere — the CSV has no rows for that date | both stores pruned |
| any date, Supabase request fails | D1 only, silently | error swallowed in the route |

Other "history" buttons do NOT behave the same: S-07/S-08 (scan) and D-03 (data page) use `/export`, which returns D1 only whenever D1 holds any row of the symbol; R-11/T-11 (radar range copy) read one `/day` per date, which never unions stores inside a day.
